# 搜索收录与公开页面

用于需要搜索引擎发现的网站或明确的收录任务。内部工具、个人账户页和管理后台不必为了 SEO 改造。技术可抓取、提交成功、实际收录和搜索排名是不同状态。

## 先诊断当前页面

- 检查线上 HTTP 状态、原始 HTML、robots.txt、robots 元标记、X-Robots-Tag 和 canonical；浏览器能打开不代表爬虫获得同样响应。
- 核对实际公开 URL、站点地图及站长平台已有资源。不要把另一个项目的验证状态当成本网站的状态，`site:` 搜索结果也不能替代站长平台诊断。
- 原始页面只有空容器、正文依赖脚本时，优先采用静态生成或服务端渲染；不要只改标题却保留无法发现的内容地址。
- 不能仅凭一次抓取工具失败判定所有搜索引擎被封禁。用官方实时抓取检测区分网络、安全拦截、解析和索引问题，不为了收录关闭全站防护。

## 地址、内容和权限

- 公开内容使用可独立访问的路径，如 `/items/example`，并提供普通 `<a href>` 链接。避免依赖 `/#/items/example` 区分需要收录的页面。[Google URL 指南](https://developers.google.com/search/docs/crawling-indexing/url-structure)
- 迁移 hash 路由时，服务端收不到 `#` 后的部分；保留客户端兼容转换，并检查直接访问、刷新、前进后退和旧收藏链接。不要声称服务端已对 hash 内容做了 301。
- 首页与内容页返回可见正文、独立标题、描述和规范网址。SSR 与客户端视图尽量共用模板，初次加载或 API 暂时失败时不应抹掉已有公开正文。切换页面时同步元数据。
- 真正不存在或下架的内容返回 404；个人页、后台和不应出现在搜索结果中的接口使用合适的 noindex。robots.txt 不是授权机制，也不能代替登录检查。
- 原始 HTML、初始化 JSON、站点地图和分享元数据只能包含公开字段。对嵌入 JSON 的 `<` 等字符进行安全处理，防止用户内容提前闭合 script 标签；不向已登录用户返回可能被共享缓存的私有 HTML。
- 主域名、备用域名和尾斜杠等重复地址按实际需要统一 canonical 或重定向；静态资源、认证 Cookie 和既有 API 不能因地址迁移失效。

## 站点地图与免费部署

- sitemap.xml 只列出公开、可索引、返回 200 的规范网址；robots.txt 引用其绝对 HTTPS 地址。不存在 sitemap 并非禁止抓取，但新站通常需要它帮助发现页面。
- 发布、修改、下架后地图应同步变化；lastmod 使用内容真实更新时间，不在每次请求时伪造新日期。不要反复提交同一份未变化地图。
- Workers 项目只让需要渲染或动态处理的路径进入 Worker，图片、样式和脚本继续由 Static Assets 提供。深层页面的静态引用应使用正确的根路径，测试环境使用与正式站相同的路由配置。
- SSR 会消耗 Worker 请求、CPU 和数据库读取额度。复用公开初始化数据避免首屏重复取数，并选择符合内容更新要求的缓存策略；不能把免费静态请求额度直接套用到动态页面。

## 提交与验收

用户授权提交后，使用其账号完成站点验证；登录、人机验证和必须由本人确认的个人资料由用户在官方页面完成。只索取任务所需的授权，不通过抓取浏览器凭据绕过登录。

- **Google Search Console**：添加正确的域名或 URL 前缀资源；取得对应站点的 DNS、文件或 HTML 元标记验证材料，部署后验证，再提交 sitemap，检查少量重要网址并请求编入索引。[官方提交说明](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)
- **Bing Webmaster Tools**：可单独验证，也可在用户同意相应授权后从 Search Console 导入。提交地图并检查 URL 状态；需要持续自动推送时再评估 IndexNow，不默认增加后台任务。[地图文档](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed)
- **百度搜索资源平台**：完成账号资料、站点属性和所有权验证，使用账号实际开放的普通收录或地图入口。提交配额和功能资格以当前页面为准，不承诺所有新站都有相同入口。[链接提交说明](https://ziyuan.baidu.com/linksubmit/url)

文件验证应检查验证服务实际请求的原始 URL 和响应正文；Static Assets 的 HTML 规范化可能自动跳转到无扩展名路径，遇到验证失败时可让该文件原路径直接返回 200，再向平台验证。不要只凭浏览器跟随跳转后的成功判定文件可验证。

站长平台报告安全问题但未给出样本时，记录报告、已检查范围与未检查内容；未复现或其他检测页面显示正常，都不足以证明问题已修正，不提交缺乏依据的修复声明。

验证用的公开元标记或文件需要随工程保留；它们与会话 Cookie、API 密钥不是同一类资料。不要在通用 skill 中带入个人站点验证码、域名或私有配置。

验收覆盖无脚本正文、元数据、404/重定向、地图更新、原账号权限、旧链接和移动端。正式站再核对 HTTP 响应与平台回执，分别记录「已验证」「已提交」「抓取成功」「已收录」。平台仍显示待处理或失败时如实记录，不能用本地 200 代替平台确认。请求收录可能需要数天至数周，且不保证最终收录或排名；未要求周期监测时不创建定时任务。
