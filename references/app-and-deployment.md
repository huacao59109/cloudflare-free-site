# 网站开发与发布

## 确定页面与技术方案

从网站用途、目标用户、页面结构、参考风格和主要操作开始。已有项目沿用合适的技术栈；新项目选择满足需求的最简方案，不预设某种业务或框架。

静态页面优先使用 Workers Static Assets。需要动态交互时再增加 Worker API；需要持久化数据时再选择 D1 或已有数据源。登录和后台也按需求添加。

## 完成网站

- 先落实页面内容、导航和主要操作，再完善视觉设计。
- 适配桌面与手机，确保链接、表单和交互可用。
- 文案简洁，使用实际内容；占位内容在正式发布前替换。
- 动态功能应持久保存数据，处理必要的校验、权限和错误反馈。
- 更新已有网站时保留现有数据与账号配置，避免无关重构。

具体业务字段、存储实现和组件库由当前项目决定，不作为本技能的固定要求。

## 管理功能与数据演进

按实际需求采用，不因已有组件而默认增加后台或统计。

- 可选展示板块由服务端控制公开字段；关闭展示时保留管理端保存值，避免用户再次开启时重填。管理数据与公开响应分开序列化。
- 单值改为多值时兼容旧记录，校验数量、长度及重复项，并同步更新筛选、计数、搜索和展示。默认选项与用户自定义值可以共存，不把某个业务的分类表写死为通用要求。
- 编辑保存使用版本号或等效并发检查，避免旧窗口覆盖新内容；部署与数据初始化分离。
- 统计功能明确衡量的是页面浏览、按钮点击还是流程完成，定义汇总时区、重试去重和明细保留周期。需要排除管理人员测试时，在服务端根据当前会话角色判断；匿名状态无法可靠识别管理员。
- 涉及公开内容和私有操作的页面，先划分响应数据，再选择静态生成、服务端渲染或客户端交互。不要把受保护字段塞入 HTML 或初始化 JSON 后仅靠界面隐藏。搜索需求见 [搜索收录与公开页面](search-and-discovery.md)。

## 准备部署

## 按需增加防滥用和使用额度

- 注册需要防机器人时可采用 Turnstile；实施前核对[官方免费计划](https://developers.cloudflare.com/turnstile/plans/)。在服务端调用 Siteverify，并核对 hostname 和 action，不能仅依靠前端验证成功。验证服务失败时拒绝受保护操作，并提供重试入口。公开 site key 与加密 secret 分开保存；部署时保留原登录密钥。
- 用户额度应在返回受保护结果之前，由数据库原子检查并扣除；请求重试用绑定用户、周期和操作的唯一凭据去重。周期采用明确的业务时区，管理账号豁免由服务端角色判断。测试并发临界值、重复请求、跨用户隔离和周期切换。
- 明确额度限制的是本站提供结果的次数，还是外部服务完成操作的次数；本站无法撤销已经交付的外部地址，也不能把外部完成情况当成可验证事件。
- 邮箱验证需要单独核实发信服务的免费额度和域名准入，免费建站域名不一定被发信平台接受。未验证实际发信前，不切换正式注册流程；更改身份方式应保留已有账号及权限。

使用当前项目的构建产物和配置。静态站的配置结构示例：

```json
{
  "name": "site-static",
  "compatibility_date": "2026-11-07",
  "assets": { "directory": "./public" }
}
```

名称、兼容日期和目录应按项目实际情况设置。动态站按需增加 Worker 入口与资源绑定；不要把示例直接覆盖到已有配置。让公开静态资源直接由 Assets 提供，只让必要请求进入动态处理。[Static Assets 官方文档](https://developers.cloudflare.com/workers/static-assets/)

使用用户自己的 Cloudflare 账号。新项目只创建需要的资源；已有项目核对现有绑定，保留数据和密钥。配置中不写入凭据，账号专属信息不复制到其他项目。

## 发布顺序

1. 完成构建，并检查与本次改动相关的页面和功能。
2. 确认目标账号、项目和免费套餐；已有数据需要变更时先备份并评估兼容性。
3. 使用项目锁定的工具版本预检，再发布代码。Wrangler 的常见命令为 `npx wrangler deploy --dry-run` 和 `npx wrangler deploy`。
4. 按 [域名与免费额度](domain-and-free-plan.md) 绑定自定义域名并确认 HTTPS。
5. 在正式域名验收，将线上配置和发布版本记入项目文档。

日常发布与数据初始化分开，不在每次部署时重建数据库或导入示例。源码与部署说明可以公开；密钥、登录状态和数据备份单独保管。

验收和后续更新见 [验证与维护](validation-and-maintenance.md)。
